자료구조 6주차 정리 - 스택, 큐, 해시 테이블

■ 스택(Stack)
- 데이터를 한쪽 끝에서만 넣고 빼는 선형 자료구조. 가장 나중에 넣은 데이터가 가장 먼저 나온다. 이를 LIFO(Last In First Out)라고 한다.
- 주요 연산
  · push: 맨 위(top)에 데이터를 추가
  · pop: 맨 위의 데이터를 꺼내고 제거
  · peek(top): 맨 위의 데이터를 제거하지 않고 확인
  · isEmpty: 비어 있는지 확인
- push, pop, peek 모두 O(1) 시간에 수행된다.
- 배열로 구현하면 크기가 고정되어 가득 찼을 때 push하면 오버플로가 발생한다. 비어 있을 때 pop하면 언더플로가 발생한다. 연결 리스트로 구현하면 크기 제한은 없지만 노드마다 포인터를 저장하는 추가 메모리가 든다.
- 활용 예
  · 함수 호출 스택: 함수가 호출될 때 복귀 주소와 지역 변수를 쌓고, 함수가 끝나면 꺼낸다. 재귀가 너무 깊어지면 스택 오버플로가 난다.
  · 괄호 짝 검사: 여는 괄호는 push, 닫는 괄호를 만나면 pop해서 짝이 맞는지 확인한다. 끝났을 때 스택이 비어 있어야 올바른 괄호 문자열이다.
  · 웹 브라우저 뒤로 가기, 실행 취소(undo) 기능.
  · 후위 표기식 계산: 피연산자는 push하고, 연산자를 만나면 두 개를 pop해서 계산한 결과를 다시 push한다.

■ 큐(Queue)
- 한쪽 끝(rear)에서 넣고 반대쪽 끝(front)에서 빼는 선형 자료구조. 먼저 넣은 데이터가 먼저 나온다. 이를 FIFO(First In First Out)라고 한다.
- 주요 연산: enqueue(rear에 추가), dequeue(front에서 꺼내고 제거), front(맨 앞 확인)
- 배열로 단순하게 구현하면 dequeue할 때마다 앞쪽 공간이 비어서 낭비된다. 이를 해결하기 위해 배열의 끝과 처음을 이어 붙인 것처럼 쓰는 원형 큐를 사용한다. 원형 큐에서는 인덱스를 (index + 1) % size로 이동한다.
- 원형 큐에서 front == rear이면 비어 있는 상태로 본다. 가득 찬 상태와 구분하기 위해 보통 한 칸을 비워 두고, (rear + 1) % size == front이면 가득 찬 것으로 판단한다.
- 활용 예: 프린터 작업 대기열, 운영체제의 프로세스 스케줄링, 너비 우선 탐색(BFS).
- 덱(Deque): 양쪽 끝에서 모두 삽입과 삭제가 가능한 자료구조. 스택과 큐의 기능을 모두 할 수 있다.
- 우선순위 큐: 들어온 순서가 아니라 우선순위가 높은 데이터가 먼저 나온다. 보통 힙(heap)으로 구현하며 삽입과 삭제가 O(log n)이다.

■ 해시 테이블(Hash Table)
- 키(key)를 해시 함수에 넣어 나온 값(해시 값)을 인덱스로 사용해 값을 저장하는 자료구조.
- 평균적으로 검색, 삽입, 삭제가 O(1)이다. 배열이나 연결 리스트에서 원하는 값을 찾을 때 O(n)이 걸리는 것과 비교된다.
- 좋은 해시 함수의 조건: 계산이 빠르고, 키를 테이블 전체에 고르게 분산시켜야 한다.
- 충돌(collision): 서로 다른 키가 같은 해시 값을 갖는 경우. 테이블 크기는 유한하므로 충돌은 피할 수 없고, 처리 방법이 필요하다.
  · 체이닝(chaining): 같은 인덱스에 들어온 데이터를 연결 리스트로 이어서 저장한다. 구현이 간단하지만, 한 버킷에 데이터가 몰리면 검색이 느려진다.
  · 개방 주소법(open addressing): 충돌이 나면 테이블의 다른 빈칸을 찾아 저장한다. 바로 다음 칸을 차례로 확인하는 선형 탐사가 대표적이다. 선형 탐사는 데이터가 특정 구간에 뭉치는 군집화(clustering) 문제가 생길 수 있다.
- 적재율(load factor) = 저장된 데이터 수 / 테이블 크기. 적재율이 높아지면 충돌이 늘어나므로, 일정 수준(예: 0.75)을 넘으면 테이블 크기를 늘리고 모든 데이터를 다시 해싱한다(리해싱).
- 최악의 경우 모든 키가 한 버킷에 몰리면 검색이 O(n)까지 느려질 수 있다.
